## What the course is about
Ways to represent and handle data. Data = information + meaning:
"73 109 48 25" what are these numbers?
Depending on the answer we may need to do different things with them:
- *Values from a temperature sensor?* Add one at a time to the end of the sequence; access them sequentially to compute statistics
- *Item prices in a store?* Insert and remove new products with their prices, access or update the price of a specific product
- *High scores in an online videogame?* Insert new values while keeping an ordered leaderboard, access the top N scores

DSA is about common ways to organize data on a computer, and learning how to pick the right data structure for the right task. 

In the end, the ultimate goal is to make our programs efficient; but it is orthogonal to high performance computing.
This course is about designing good algorithms, HPC is about optimizing the actual implementation of the algorithm on a machine.
You can think of a good programmer as a good chef: to make great dishes the chef needs a great recipe (DSA), and they also need to be manually skilled with kitchen tools (HPC).

## Java internals
We will spend the first few lectures talking about Java features we will use during the course. Let's start with some terminology.

How does a computer compute? Every computer has a set of **instructions**, low-level operations like moving a value from memory to a register or doing a single arithmetic operation on two values in registers.
Using these directly to describe our program would be extremely tedious, and worse, computers have different hardware, so we'd need to write many versions of the same code in several different languages to make our code available to many.
Instead, we write a program specification in some high-level language and automate the generation of machine code.

Languages like C/C++, Fortran or Rust are *compiled*, meaning that you have a *compiler* program that takes human-readable **source code** and turns it into machine code for a specific machine. This is good because the compiler does a lot of optimizations for us and the code is made very efficient for the specific machine. But we still need to compile our code on different machines, and recompile it every time it changes, which can take time.

Languages like Python, JavaScript or Lua are *interpreted*, meaning that you have an *interpreter* program that reads human-readable source code and turns it into instructions live as it reads them. This is less efficient because there is less room for optimization, but any machine running the interpreter can execute the same program, without ever calling a compiler.

**Java** does a bit of both: it has a compiler that turns source code into an intermediate representation called **bytecode**, which allows some optimizations but it is **not** machine code yet. Then, every machine that wants to run a Java program needs a JVM installed, which interprets the optimized bytecode (or compiles it on the fly, but we won't get into that). The slogan of Java is "write once, run anywhere" - we still need to compile our program every time it changes, but the output of compilation can be executed by a JVM on any machine without recompilation.

When you submit your assignments, you could in theory just provide us the .class files directly. But we need to check your source code.

## Memory organization
Computers have memory that programs can use to store data as they run.
Consider the following Java statement: int x=5; what does it do?
A declared variable has a name, a type, and a memory address. When we assign it, it also gets a value.
Q: What does each of these do?
Variables in Java behave differently depending on whether they are of primitive or reference type.

Every byte (8 bits) of memory has a unique address.
In general we never care about what the actual memory addresses are, just what they point to.

### Primitive types
(draw memory for `int x=5;`, `float x=5`, `double x=5`)
Variables of primitive types behave as you expect. Their value is stored at the memory address of the variable.
Primitive types are only these, with their byte sizes:
type 	number of bytes
byte 	1 byte
char, short 	2 bytes
int, float 	4 bytes
long, double 	8 bytes
boolean 	may vary

### Reference types
Any other type is either an array, a user-defined class, or imported from a library (including the Java Class Library).
Suppose we define a class `Circle`: what happens when we write `Circle c = new Circle(5);`?
We don't store the actual data of `Circle` at the address of c; we keep it somewhere else in memory, and c's location just contains a memory address that "redirects" us to the correct spot in memory. More on why later.
